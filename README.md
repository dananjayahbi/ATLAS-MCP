# ATLAS-MCP

Multi-Agent Task & Logging Archive System — a local, single-operator control plane
for orchestrating several coding agents against several repositories.

Agents claim work through MCP tools; a Cyber-HUD dashboard shows the live board,
priority matrix, annotation canvas and streamed agent logs. Everything runs on
loopback; SQLite is the only datastore.

---

## Quick start

```powershell
# 1. Backend dependencies (Python 3.11+)
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt

# 2. Frontend dependencies (Node 20+)
npm --prefix frontend install

# 3. Generate .env files, migrate, and print the MCP client snippet
.\.venv\Scripts\python.exe scripts\bootstrap_dev.py

# 4. Optional: realistic demo data (2 projects, 13 tasks, discoveries, review)
.\.venv\Scripts\python.exe scripts\seed_demo.py

# 5. Start both servers — two CMD windows, production frontend
.\start-atlas.bat
```

`start-atlas.bat` is the normal way to run the stack:

| Command | What it does |
| :--- | :--- |
| `start-atlas.bat` | Preflight, port checks, build if stale, open two windows, wait for both health checks |
| `start-atlas.bat --rebuild` | Force a fresh `next build` before starting |
| `start-atlas.bat --no-wait` | Open the windows without polling for readiness |

It opens **two independent CMD windows**:

| Window | Command | URL |
| :--- | :--- | :--- |
| `ATLAS backend :8471` | `uvicorn atlas.asgi:application` (ASGI, needed for SSE) | http://127.0.0.1:8471 |
| `ATLAS frontend :3471` | `next start` on the built `.next` bundle — **not** `next dev` | http://127.0.0.1:3471 |

Both windows tee their output to `logs/backend.log` and `logs/frontend.log`.
Closing a window stops that server.

Override the ports for one run without editing anything:

```powershell
$env:ATLAS_BACKEND_PORT = "8532"
$env:ATLAS_WEB_PORT     = "3532"
.\start-atlas.bat
```

Ports are deliberately uncommon (`8471`/`3471`) so they do not collide with other
local projects. To change them permanently, update `.env` and `frontend/.env.local`
(both are generated by `bootstrap_dev.py`).

### MCP in VS Code

`bootstrap_dev.py` writes `.vscode/mcp.json` with the real token from `.env`, so the
`atlas` server is available to Copilot Chat immediately — no manual copying.

`.vscode/mcp.json` is gitignored because it contains the token. The committed
[.vscode/mcp.example.json](.vscode/mcp.example.json) shows the same shape using a
`${input:atlas-api-token}` prompt instead. Regenerate or validate at any time:

```powershell
.\.venv\Scripts\python.exe scripts\write_mcp_config.py           # write + validate
.\.venv\Scripts\python.exe scripts\write_mcp_config.py --check   # validate only
```

Because the MCP server is a plain stdio process, you can drive it without VS Code:

```powershell
.\.venv\Scripts\python.exe scripts\mcp_probe.py   # 10 live conformance checks
```

## The contract

`plan-series/01_system_architecture.md` is the frozen authority. Every other doc
and every line of code defers to it. The pieces most worth knowing:

| Concept | Value |
| :--- | :--- |
| Contract version | `1.0.0` |
| Task statuses | `PENDING_APPROVAL`, `PENDING`, `IN_PROGRESS`, `IN_REVIEW`, `COMPLETED`, `REJECTED` |
| Lease TTL / heartbeat / grace | 900 s / 120 s / 60 s |
| MCP token ceiling | 16 384 bytes per tool response |
| Max patch | 5 MB |
| Ports | backend 8471, frontend 3471, loopback only |

**Why the claim is a single `UPDATE`:** SQLite has no `SELECT … FOR UPDATE`, and
Django silently ignores `select_for_update()` on it. The claim is therefore a
conditional single-statement `UPDATE … WHERE status='PENDING'` inside an
`IMMEDIATE` transaction; the affected-row count is the linearisation point.
See `backend/core/leases.py` and Doc 01 §11.

## Operator workflows

The HUD is keyboard-first; every action below is reachable without a mouse.

| Task | Where | Shortcut |
| :--- | :--- | :--- |
| Register a project | `＋ New` in the top bar, or `+ New project` in the rail | — |
| Create a task | `New task` on a project board | `n` |
| Search / filter tasks | Search bar above the board (debounced, URL-synced) | `/` |
| Bulk reprioritise / requeue / archive | Select rows with the checkbox, then the bulk bar | `x` selects, `Esc` clears |
| Triage discoveries | `/discoveries` — approve, edit priority, or dismiss | `j`/`k`, `a`, `e`, `Del`, `u` |
| Sign off a review | `/reviews` — inspect the patch, then sign off | `⌘/Ctrl+Enter` |
| Return to a dashboard | `▦ Dashboard` in the top bar (last project used) | — |
| Keyboard map | `?` opens the cheat sheet | `?` |

Board filters round-trip through the URL (`?q=`, `?status=`, `?agent=`,
`?blocked=`, `?pmin=`, `?sort=`), so a filtered board is shareable and survives a
reload. Search is debounced by 250 ms so typing never pushes a history entry per
keystroke.

**Bulk actions are sequential, never `Promise.all`.** Concurrent priority patches
on one task race the `BEGIN IMMEDIATE` writer and produce spurious
`STALE_LEASE`. The bar reports `n succeeded, m failed`. Approving a review in bulk
is deliberately not offered — T8 is the only hard human gate.

### Throttling

Doc 04 §3.4 fixes three budgets, enforced per caller in
`backend/api/common/throttle.py`:

| Scope | Rate | Applies to |
| :--- | :--- | :--- |
| `read` | 600/min | `/api/v1` **GETs** |
| `upload` | 20/min | `POST /assets/` |
| `internal` | 120/min | `/internal/v1/*`, keyed by `X-ATLAS-Agent` |

Human mutations (`POST`/`PATCH`/`DELETE` under `/api/v1`) are deliberately
unthrottled: the surface is loopback single-operator, and metering writes would
let a bulk action throttle itself part-way through its own row loop.

A rejection is `RATE_LIMITED` → **429** with `Retry-After`. The HUD retries that
once, honouring the header (`frontend/lib/api/client.ts`). Returning 500 here
would misreport an ordinary burst as a backend fault and would select the
`INTERNAL_ERROR` retry path instead — which is exactly the defect the
`test_throttle_rejection_is_429_with_retry_after` regression test pins.

## Design decisions worth knowing

- **One writer, WAL, `IMMEDIATE` transactions.** Readers never block; the write
  lock is taken at `BEGIN` so two claims cannot interleave.
- **Files before rows.** A file is written and `fsync`ed before the row that
  references it, so a row with a path always points at real bytes. Writes go to
  a temp file in the same directory, then `os.replace` (atomic on one volume).
- **Dual-path rule.** The DB stores POSIX-relative asset paths; absolute native
  paths are derived at response time. Moving the repo does not invalidate rows.
- **SSE, not WebSockets.** Unidirectional, `EventSource` reconnects for free, and
  a Next.js rewrite cannot proxy WS upgrades. Two routes: one per project, one
  per task.
- **The browser never holds the token.** `/api/v1/*` is proxied by a Next.js
  route handler that injects `Authorization` server-side.
- **`skipTrailingSlashRedirect` is mandatory.** Django's routes end in `/` and
  Django cannot `APPEND_SLASH` a POST body, so the proxy forwards the raw
  pathname. Turning this off makes every mutation answer `308` then `500`.
- **`stream.reset` means "your cursor is unusable", not "welcome".** A fresh
  client replays history; only an unresolvable `Last-Event-ID` or a replay gap
  produces a reset. Emitting it on every connect pins the HUD in DEGRADED.
- **Agents are token-constrained.** The claim projection carries no timestamps,
  no event history, no base64 — and is hard-capped at 16 384 bytes.
